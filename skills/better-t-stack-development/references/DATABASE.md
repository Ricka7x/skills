# Database (Drizzle ORM + PostgreSQL)

## File Locations

```
packages/db/src/
├── index.ts          → exports db instance, eq, and, etc.
└── schema/
    ├── index.ts      → re-exports all schema files
    ├── auth.ts       → better-auth generated tables (don't edit manually)
    └── *.ts          → your domain tables
```

## Schema Conventions

### Required Columns

Every table must have:
```ts
id: text("id").primaryKey(),                          // string UUID
createdAt: timestamp("created_at").defaultNow().notNull(),
updatedAt: timestamp("updated_at")
  .defaultNow()
  .$onUpdate(() => new Date())
  .notNull(),
```

> `updatedAt` is required for **mutable** tables. Append-only/event tables (audit logs, ledger entries) can omit it — they should never change after insert.

### Full Table Example

```ts
import { relations } from "drizzle-orm";
import {
  boolean,
  index,
  integer,
  pgTable,
  text,
  timestamp,
  uniqueIndex,
} from "drizzle-orm/pg-core";
import { user } from "./auth";

export const post = pgTable(
  "post",
  {
    id: text("id").primaryKey(),
    title: text("title").notNull(),
    content: text("content"),
    published: boolean("published").default(false).notNull(),
    userId: text("user_id")
      .notNull()
      .references(() => user.id, { onDelete: "cascade" }),
    createdAt: timestamp("created_at").defaultNow().notNull(),
    updatedAt: timestamp("updated_at")
      .defaultNow()
      .$onUpdate(() => new Date())
      .notNull(),
  },
  (table) => [
    index("post_userId_idx").on(table.userId),
  ]
);

export const postRelations = relations(post, ({ one }) => ({
  user: one(user, { fields: [post.userId], references: [user.id] }),
}));
```

### Rules

- **IDs:** Always `text("id").primaryKey()` — generated by `crypto.randomUUID()` in handlers (or by better-auth for auth tables)
- **Foreign keys:** `onDelete: "cascade"` for **owned aggregates** (rows that exist only because their parent does). For audit/log/history or rows you must never lose, use `"set null"` / `"restrict"` — cascades are destructive and can silently wipe data you needed to keep.
- **Indexes:** Add indexes on any column used in `WHERE` clauses or joins (especially FK columns)
- **Nullable columns:** Omit `.notNull()` to allow null — prefer explicit over implicit
- **Booleans:** Always provide `.default(false)` or `.default(true)` — never leave boolean nullable
- **Column names:** Use snake_case in the DB (`"user_id"`), Drizzle maps to camelCase in TS (`userId`)
- **Table names:** snake_case singular (`"post"`, `"organization_member"`)

### Column Types Reference

```ts
text("col")                          // VARCHAR / TEXT
boolean("col")                       // BOOLEAN
integer("col")                       // INTEGER
timestamp("col")                     // TIMESTAMP
uniqueIndex("idx_name").on(table.col) // unique constraint via index
index("idx_name").on(table.col)       // regular index
```

## Relations

Always define Drizzle relations alongside the table for query API support:

```ts
// One-to-many
export const userRelations = relations(user, ({ many }) => ({
  posts: many(post),
}));

export const postRelations = relations(post, ({ one }) => ({
  author: one(user, { fields: [post.userId], references: [user.id] }),
}));

// Many-to-many (via join table)
export const tagRelations = relations(tag, ({ many }) => ({
  postTags: many(postTag),
}));

export const postTagRelations = relations(postTag, ({ one }) => ({
  post: one(post, { fields: [postTag.postId], references: [post.id] }),
  tag: one(tag, { fields: [postTag.tagId], references: [tag.id] }),
}));
```

## Querying

Import `db`, `eq`, `and` from `@condomin-ia/db`:

```ts
import { db, eq, and } from "@condomin-ia/db";
import { post } from "@condomin-ia/db/schema";
// or import specific schema: import { post } from "@condomin-ia/db/schema/post";

// Find one
const item = await db.query.post.findFirst({
  where: eq(post.id, id),
  with: { author: true },  // uses relations
});

// Find many with filter
const items = await db.query.post.findMany({
  where: and(
    eq(post.userId, userId),
    eq(post.published, true)
  ),
  orderBy: (post, { desc }) => [desc(post.createdAt)],
  limit: 20,
  offset: 0,
});

// Insert — id required, timestamps auto-fill (defaultNow)
const [created] = await db.insert(post)
  .values({ id: crypto.randomUUID(), title, userId })
  .returning();

// Update — updatedAt auto-fills via $onUpdate
const [updated] = await db.update(post)

  .where(eq(post.id, id))
  .returning();

// Delete
await db.delete(post).where(eq(post.id, id));
```

## Auth Schema

The `packages/db/src/schema/auth.ts` file is **generated by better-auth CLI** — never edit it manually.

After adding or changing better-auth plugins, regenerate:
```bash
bun plugin:generate
```

Then run:
```bash
bun db:generate  # Create migration files
bun db:push      # Apply to DB (dev only — use db:migrate in prod)
```

## CLI Commands

```bash
bun db:generate   # Generate Drizzle migration files from schema changes
bun db:push       # Push schema directly to DB (dev only, no migration files)
bun db:migrate    # Run pending migrations (production)
bun db:studio     # Open Drizzle Studio (visual DB browser)
bun db:start      # Start local PostgreSQL via Docker
bun db:stop       # Stop local PostgreSQL
bun db:down       # Tear down Docker containers
```

## Anti-Patterns

- ❌ Use auto-increment integer IDs — always `text("id").primaryKey()`
- ❌ Edit `schema/auth.ts` manually — use `bun plugin:generate`
- ❌ Forget `onDelete: "cascade"` on FK references
- ❌ Skip indexes on FK columns — always index foreign keys
- ❌ Leave booleans without a default value
- ❌ Use `db:push` in production — use `db:migrate`
